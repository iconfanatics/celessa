# Theme Accessibility & Performance Work Log

## Accessibility Fixes (Agentic Browsing)
- **Discernible Text on Slider Links**: Added `aria-label` to `.hero__slide-link` in `sections/slideshow.liquid` and `snippets/page-block-image-hero.liquid` to ensure screen readers can read where the slide links to.
- **Slick Slider ARIA Fixes**: Disabled slick slider's automatic accessibility attributes globally by setting `accessibility: false` in `assets/theme.js.liquid`. This prevents slick from injecting invalid ARIA states (`role="presentation"` with `aria-selected`, missing accessible names on `listbox`).
- **Discernible Text on Promo Grid Links**: Added `aria-label` to anchor tags wrapping promotional images in `snippets/promo-grid.liquid` (covering `sale_collection`, `image`, and `banner` blocks).
- **Cleanup**: Removed the previously added `slick-accessibility-fix.liquid` hack as disabling the native slick accessibility option natively resolves the issue more cleanly.
- **Appropriate ARIA Roles for Navigation**: Removed invalid `role="navigation"` from the `ul` element in `snippets/header-desktop-nav.liquid` to conform to ARIA standards for `ul` tags.
- **Discernible Text on Newsletter Button**: Added `aria-label` to the submit button (`.footer__newsletter-btn`) in `snippets/footer-newsletter.liquid`.
- **Third-Party App (Loox) Accessibility**: Added a `MutationObserver` script to `layout/theme.liquid` (just before `</body>`) to dynamically inject `aria-label="Close dialog"` on `.loox-pn-close` links and `aria-label="Powered by Loox"` on `.loox-pn-branding` links, ensuring screen readers can announce them properly.
- **Slick Slider ARIA Fixes (Global Vendor Override)**: Further hardened the Slick accessibility fix by overriding `accessibility: !0` to `accessibility: !1` directly inside the core Slick plugin source (`assets/vendor-scripts-v6.js`) and adding `accessibility: false` to `mainSliderArgs` in `assets/theme.js.liquid`. This ensures zero invalid ARIA attributes are generated for any carousel site-wide.
- **Product Review Link**: Added `aria-label="Reviews"` to `.product-single__review-link` in `sections/featured-product.liquid` and `snippets/product-template.liquid` to provide discernible text.
- **Slick Slider ARIA Hidden Focus Fix**: Expanded the `MutationObserver` in `layout/theme.liquid` to actively monitor and strip the `aria-hidden="true"` attribute from ALL `.slick-slide` elements (not just cloned ones) AND `.slick-dots li` (pagination dots) as soon as they are added to or modified in the DOM. This ensures that no slide or pagination dot is ever improperly hidden while containing focusable elements, completely eliminating the "ARIA hidden element must not be focusable" error on product sliders, thumbnails, and pagination globally.
- **Product Image Zoom Button**: Added `aria-label="Zoom image"` to `.product__photo-zoom` in `snippets/media.liquid` to ensure discernible text for screen readers.
- **Rich Text / App Widget Contrast Fix**: Added a global CSS override in `assets/theme.scss.liquid` (`span[style*="Nunito Sans"] { color: $colorTextBody !important; }`) to ensure that third-party app widgets (like Discount Ninja) and pasted rich text with light inline font colors correctly inherit the theme's high-contrast body text color, fixing Lighthouse contrast ratio errors on promotional text (e.g. "FRESHÉ • INTIMATE LAUNDRY SHEETS", "RM200+").
- **Web Font Display Swap Optimization**: Updated `snippets/font-face.liquid` and `sections/instafeed.liquid` to append the `font_display: 'swap'` parameter to all Shopify `font_face` filters. This ensures that browsers display fallback fonts while the custom theme fonts (like Nunito Sans) are downloading, eliminating the "Ensure text remains visible during webfont load" (FCP) error in Lighthouse.

## Note on DevTools & Lighthouse Console Warnings
During testing, you may encounter the following console errors/warnings in Lighthouse or Chrome DevTools. These are generated by Shopify's core scripts and browser configurations, and are **not** theme issues:
1. **`Uses deprecated APIs (Attribution Reporting)`**: This warning comes from Shopify's own analytics tracker (`shop_events_listener.js`). It is a server-side Shopify script that will be updated by Shopify's team globally.
2. **`ERR_BLOCKED_BY_CLIENT (otlp-http-production.shopifysvc.com)`**: This indicates that the testing browser has an Adblocker (like uBlock Origin) or strict privacy shields (like Brave) enabled, which is blocking Shopify's telemetry/tracking pings. It does not affect normal visitors.
3. **`403 Error / Content Security Policy (shop.app)`**: This is caused by Shopify's internal Content Security Policy blocking the loading of the Shop app or Shop Pay features inside an iframe (often happens while inside the Shopify Theme Editor). 

None of the above errors affect the theme's code, performance, or real-world user experience.
